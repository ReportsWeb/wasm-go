# 01.あっという間に帳票出力 — Go

> このサンプルは Go モジュール [`github.com/ReportsWeb/wasm-go/reportsweb`](../reportsweb/README.md) と、帳票エンジンの Docker イメージ [`ghcr.io/reportsweb/engine`](https://github.com/ReportsWeb/engine) を使っています。

Goで1ページの印刷データを作り、ブラウザーで表示・PDF保存する、最初のサンプルです。短いGoコードの文字を変えて、帳票に反映されるところから始めます。

## デザインも変えてみましょう

このサンプルは、出力を見るだけでなく、デザイナーで文字・色・配置を自由に変え、プレビューとPDFに反映するところまで体験できます。

起動したら、画面上部の「デザイナーでデザインを変更」を押します。編集後に「変更を反映してプレビューへ戻る」を押すと、プレビューと「PDFを保存」の両方が編集後の内容になります。「変更せず戻る」なら変更を取り消せます。

この操作はブラウザー内の体験用です。プログラムが設定した文字も編集できるよう、現在の値をデザインへ入れて開きます。元の帳票ファイルやプログラムは上書きしません。ページを再読み込みすると元のサンプルに戻ります。編集結果を残す場合は、戻る前にデザイナーの保存機能で `.prepdj` を保存してください。ソースの値を変える練習とは別の操作です。

## 1. 用意するもの

- **Windows／macOS**：Docker Desktopをインストールして起動してください。WindowsではLinuxコンテナーを使用します。macOSでは、お使いのMac（Apple Silicon／Intel）に合うインストーラーを選びます。
- **Linux**：Docker EngineとDocker Composeプラグインを用意し、Dockerサービスを起動してください。Docker Desktopを使うこともできます。
- ターミナルで `docker version` と `docker compose version` が実行できる状態にしてください。以下のDockerコマンドは3 OS共通です。[Docker公式の導入案内](https://docs.docker.com/compose/install/)
- 初回はDockerが必要なソフトウェアを取得するため、インターネット接続が必要です。
- GoやNode.jsをパソコンへ別途インストールする必要はありません。
- このリポジトリを `git clone` して、番号フォルダーでコマンドを実行します。帳票エンジンは Docker イメージ `ghcr.io/reportsweb/engine:1.0.0` として自動で取得されます。

## 2. 開発環境で開いて起動する

1. VS CodeやCursorの「ファイル → フォルダーを開く」で、**このREADMEがある `01.あっという間に帳票出力` フォルダー**を開きます。
2. 「ターミナル → 新しいターミナル」を開きます。
3. 次のコマンドを入力してEnterを押します。Vimなど別のエディターを使う場合も、このフォルダーへ移動したターミナルで同じコマンドを実行します。

```sh
docker compose up -d --build --wait --wait-timeout 180
```

この操作でGoのWebサーバーと帳票エンジンが起動します。初回のビルドには数分かかることがあります。フォルダーをクリックしただけでは起動しません。

4. コマンドがエラーなく終了したら、起動状態を確認します。

```sh
docker compose ps
```

quick-startとengineが `Up`（起動中）になっていることを確認します。

5. **ここまで成功してから**、[http://127.0.0.1:19250/](http://127.0.0.1:19250/)をブラウザーで開きます。

このURLは、お使いのパソコン内で今起動したサーバーの入口です。公開デモサイトではないため、起動前にURLだけ開いても動きません。ポートを外部へ開放する設定も不要です。

同じフォルダーの `Start.ps1`（Windows）／`sh start.sh`（macOS・Linux）でも、上と同じDockerコマンドを実行できます。

## 3. 画面で確かめる

1. 「あっという間に帳票出力」「株式会社パオ」と書かれた1ページが表示されます。
2. 上部の「PDFを保存」を押し、同じ内容のPDFを開きます。

PREPDJは帳票のデザイン、PREPEJはデータを流し込んで完成した印刷データです。PREPEJは保存して渡したり、後からプレビュー・再印刷したりできます。

上部の「ツールバーを非表示」で、帳票だけの表示も試せます。設定画面でボタンをすべて消した場合も、プレビューの外にある「ツールバーを表示」で元に戻せます。

## 4. ソースを一か所変えてみる

`main.go`を開き、次の文字を探します。

```go
if err = report.SetValue("CustomerName", "株式会社パオ"); err != nil { return nil, err }
```

`"株式会社パオ"`を`"サンプル商事"`に変更して保存します。Goのソースはコンパイルが必要なので、ブラウザーを開き直す前に次を実行します。

```sh
docker compose up -d --build --wait --wait-timeout 180
```

起動完了後にブラウザーを再読み込みし、文字とPDFを確認します。元に戻すときも、編集行を戻して同じコマンドで再ビルドしてください。

## 5. どこを読むか

|場所|役割|
|---|---|
|`main.go`|帳票定義を読み、表示文字を指定する中心部分|
|`definition/quick-report.prepdj`|1ページの帳票デザイン|
|[`reportsweb`](../reportsweb/README.md)（Go モジュール）|値とページをPREPEJへまとめる`Builder`と、エンジンへ送る`Engine`|
|`index.html`|Goから受け取った印刷データをプレビュアーへ渡す画面|
|`compose.yaml`|このサンプルで起動するサービスと接続先|
|`Dockerfile`|Goの実行環境の作り方|

まず`main.go`を読み、その後に[`reportsweb`](../reportsweb/README.md)の使い方、画面へ進めば十分です。

デザインは`definition/quick-report.prepdj`をReports Webデザイナーで開いて編集できます。保存先をこのファイルに戻し、第4節のコマンドで再ビルドしてから帳票を読み込みます。

## 6. 処理を追う（必要な方へ）

```sh
docker compose logs -f quick-start
```

一時的に `log.Printf("確認したい値: %v", value)` をコードへ加えると、再ビルド後の処理をログで追えます。Ctrl+Cで終わるのはログ表示だけです。このサンプルにはリモートデバッグ設定を同梱していません。

## 7. 停止・削除して片付ける

### 一時停止する（あとで続きを試す）

このサンプルのフォルダーで実行します。

```sh
docker compose stop
```

コンテナーとDBデータを残して停止します（01はDBを使いません）。再開は `docker compose start` です。

### コンテナーと試用データを削除する

このサンプルのターミナルで実行します。

```sh
docker compose down --volumes
```

このサンプルのコンテナーとネットワークを削除します。編集したGoや帳票定義は消えません。別の01・02・03は停止しません。

同梱の `Stop.ps1`／`sh stop.sh`でも同じ操作ができます。

### サンプル用イメージも削除して、最初から試す

デバッグ中なら、先にエディターのデバッグを終了してください。このサンプルのフォルダーで次を実行します。

```sh
docker compose down --rmi local --volumes --remove-orphans
```

このサンプルのコンテナー、ネットワーク、DBデータ、ビルドしたサンプル用イメージを削除します。DBへ加えた変更は失われますが、パソコン上のGoソース、帳票定義、初期化SQLは消えません。DBは次の起動で初期データから作り直されます。01はDBを使いません。

削除できたか確認します。

```sh
docker compose ps -a
docker image ls reports-web-go-01-quick-start
```

コンテナーとイメージの一覧が、どちらも見出しだけなら削除済みです。01・02・03を全部片付けたい場合は、各フォルダーでこの削除手順を実行してください。

**他のサンプルでも使うGo・PostgreSQL・Node.jsなどの基本イメージと、ビルドキャッシュは残します。** これらは起動中のアプリではないため、残っていてもURLは開けません。他の作業を巻き込むDocker全体の一括削除は不要です。

再確認するときは、第2節の起動コマンドを実行してからURLを開きます。ビルドキャッシュも使わず、サンプルのビルド手順を確認したい場合は次を使えます。

```sh
docker compose build --no-cache
docker compose up -d --wait --wait-timeout 180
```

参考：[Docker公式の削除オプション](https://docs.docker.com/reference/cli/docker/compose/down/)。

## 困ったとき

- **dockerが見つからない／接続できない**：Docker Desktop、またはLinuxのDockerサービスが起動しているか確認し、新しいターミナルで `docker version` を実行します。Linuxで権限エラーになる場合は、Dockerの導入手順に従って実行ユーザーの権限も確認してください。
- **ポートが使用中**：`docker ps` で、すでに同じサンプルが起動していないか確認します。別環境が使っている場合は、このフォルダーに `.env` を作り、例えば `SAMPLE_PORT=19350` と書いて再度起動します。その場合のURLもその番号になります。
- **エンジンのイメージを取得できない**：インターネットに接続した状態で `docker pull ghcr.io/reportsweb/engine:1.0.0` が成功するか確認します。
- **画面が開かない／帳票が出ない**：`docker compose ps` と `docker compose logs --tail=50` を確認します。起動に失敗したままURLだけ開き直しても直りません。
- **Goの処理を追いたい**：`docker compose logs -f quick-start`でログを見られます。Ctrl+Cはログ表示を終了するだけで、サーバーは停止しません。

## 共通のファイルについて

帳票エンジンとブラウザー用のランタイム（デザイナー・プレビュー画面）は、Docker イメージ `ghcr.io/reportsweb/engine:1.0.0` から取得します。この01ではDBを使いません。

**起動するコンテナーはサンプルごとに独立しています。** 01専用のエンジンを起動します。共通のファイルを読むことと、同じ起動中のサーバーを使うことは別です。
